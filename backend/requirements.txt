# psycopg (v3), not psycopg2-binary: psycopg2-binary's wheel coverage lags
# behind new Python releases (e.g. no prebuilt wheel for 3.14 on macOS at
# time of writing, which forces a source build requiring pg_config/libpq
# even though most local dev never touches Postgres at all, since SQLite is
# the default DATABASE_URL). psycopg[binary] tracks new Python versions much
# faster. SQLAlchemy 2.0 supports psycopg v3 via the same "postgresql+psycopg://"
# dialect prefix -- only the URL scheme changes, not any application code.
# Pinned to the last 3.2.x release rather than the newest 3.3.x to stay on
# the same minor line verified in this project's own Postgres testing.
